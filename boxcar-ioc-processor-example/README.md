# Boxcar IoC :: Processor Example

A small Jakarta EE-style application tested with the `com.boxcar.Injector` generated by the annotation
processor, set up the way a real project would be. The application (`src/main/java`) knows nothing
about the injector; it is written against the Jakarta APIs only:

* `GreetingService` — a `@Stateless` bean with an injected repository *interface*, an `@EJB` reference
  to `GreetingLog`, a container-provided dependency (`java.time.Clock`) and a `@PostConstruct` method.
* `InMemoryGreetingRepository` — the only implementation of `GreetingRepository`, in a different
  package from the service.
* `GreetingLog` — a `@Singleton`.

## Setup

The processor is a test-scoped dependency, so javac discovers it through `META-INF/services` during
the test compilation only; the generated `Injector` never ships with the application. Because the
processor is on the compile class path, it can find every class below the configured package prefix —
`com.example.greetings.service` and `com.example.greetings.repository` alike ([`pom.xml`](pom.xml)):

```xml
<dependency>
    <groupId>com.boxcar</groupId>
    <artifactId>boxcar-ioc-processor</artifactId>
    <version>1.0-SNAPSHOT</version>
    <scope>test</scope>
</dependency>
```

```xml
<execution>
    <id>default-testCompile</id>
    <configuration>
        <compilerArgs>
            <arg>-Aboxcar.packages=com.example.greetings</arg>
            <arg>-Werror</arg>
        </compilerArgs>
    </configuration>
</execution>
```

`-Werror` is there to demonstrate that the processor is silent about injection points it cannot
resolve at compile time (the `Clock`): those are reported at runtime, by the test that forgets to bind
them. The generated source can be read in `target/generated-test-sources/test-annotations/com/boxcar/Injector.java`
after a build.

## Tests

[`TestInjector`](src/test/java/com/example/greetings/TestInjector.java) extends `Injector` and binds
the project's defaults in its constructor: just a fixed `Clock`. `GreetingRepository` needs no
binding, because the processor saw at compile time that `InMemoryGreetingRepository` is its only
implementation. Each test creates a fresh `TestInjector` and overrides only what it is about — a later
`bind` replaces an earlier one until the type is first resolved.

[`GreetingServiceTest`](src/test/java/com/example/greetings/GreetingServiceTest.java) is **identical**
to the one in [`boxcar-ioc-reflection-example`](../boxcar-ioc-reflection-example): the tests do not
depend on which implementation is on the class path.
